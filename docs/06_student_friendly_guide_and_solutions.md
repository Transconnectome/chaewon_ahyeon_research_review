## 1. [주제 1] Neuroprobe 15개 세부 과제: 왜 보정을 하나요? 어떻게 고치나요?

### 1.1 쉬운 설명 (30초 이해)
동전을 던져 앞면이 연속 5번 나올 확률은 약 3%(0.05 미만)라서 1번 실험에서 나오면 "신기하다!"고 할 수 있습니다. 하지만 **15명이 동시에 동전을 던지면**, 그중 누군가 1명 이상이 우연히 기준을 넘을 확률이 **$1 - 0.95^{15} = 53.7\%$**로 절반을 넘어갑니다.

Neuroprobe 안에는 `onset`, `speech`, `pitch`, `word_gap` 같은 세부 과제가 **15개** 들어 있습니다.
- 그래서 우리 논문의 **주 판정(본문 결론)**은 15개를 쪼개지 않고 **3개 벤치마크 평균 점수(`rule3`) 단 1개**로 내렸습니다. 이 설계는 통계적으로 아주 올바릅니다!
- 다만 **부록 C**에 15개 세부 과제 표를 실을 때, 심사위원이 *"15개를 보정 없이 늘어놓았는데 그중 나빠진 게 숨어 있거나, `word_gap`(+0.0078) 오른 게 우연 아닌가요?"*라고 물을 수 있습니다.
- 이때 쓰는 표준 방법이 **Benjamini-Hochberg FDR ($q$-값)**입니다. 쉽게 말해 15개의 $p$-값을 작은 순서대로 줄 세운 뒤 `p값 × (15 / 순위)`를 곱해 **"15개를 한꺼번에 본 것을 감안한 진짜 유의확률($q$-값)"**로 바꿔 주는 것입니다.

### 1.2 우리가 실제 파일을 돌려 찾아낸 두 가지 핵심 사실
1. **개수 세기 오타 발견 (`split_np_summary.json` 직접 검산)**:
   - 초안(`draft_user_20261109.md:61`, `8_figs.md:88`, 슬라이드 6쪽)에는 `1/64: 유지 6, 판정 불가 9, 깨짐 0` / `1/1024: 유지 8, 판정 불가 7, 깨짐 0`으로 적혀 있습니다.
   - 실제 `split_np_summary.json`의 15개 행을 정확히 세어 보면:
     - **`1/64`: 유지 5개 (`delta_volume`, `gpt2_surprisal`, `onset`, `pitch`, `speech`), 판정 불가 10개, 깨짐 0개**
     - **`1/1024`: 유지 7개 (`delta_volume`, `gpt2_surprisal`, `onset`, `speech`, `word_gap`, `word_index`, `word_length`), 판정 불가 8개, 깨짐 0개**
2. **왜 `판정 불가`가 8~10개나 되나요? (모델이 나빠서가 아닙니다!)**:
   - `face_num`(세션 1개), `frame_brightness`(세션 1개), `global_flow`(세션 2개), `word_head_pos`(세션 2개)처럼 **평가 데이터가 환자 1~2명분밖에 없는 과제**들은 원래 측정 흔들림(오차구간)이 넓어서 `±0.02`씩 벌어집니다. 그래서 `-0.005` 기준선 안으로 좁혀지지 못할 뿐, 평균이 나빠진 것이 아닙니다.
   - 실제로 15개 모두 FDR 보정($q < 0.05$)을 해보면 **점수가 유의하게 떨어진 과제는 1/64와 1/1024 모두 `0개`**입니다!
   - 또한 1/1024에서 무보정으로 양(+)으로 보였던 `word_index`(`+0.0074`, $p=0.035$)는 보정 후 **`q = 0.265`가 되어 우연한 흔들림이었음**이 깔끔하게 정리됩니다.

### 1.4 직접 확인하거나 `split_np.py`에 추가하는 코드 (10줄)

만약 `hangang/experiments/20261107_lead_top/split_np.py` 끝에 직접 붙이고 싶다면 외부 라이브러리 없이 아래 12줄만 넣으면 됩니다:
```python
import math

def p_two_sided_df5(t_val: float) -> float:
    """n=6 (자유도 df=5) 양측 t-검정 정확한 p-값"""
    th = math.atan(abs(t_val) / math.sqrt(5.0))
    return max(0.0, 1.0 - (2.0 / math.pi) * (th + (2.0 / 3.0) * math.sin(2 * th) + (1.0 / 12.0) * math.sin(4 * th)))

def bh_fdr_qvalues(p_list: list[float]) -> list[float]:
    """Benjamini-Hochberg 다중비교 보정 q-값"""
    m, order = len(p_list), sorted(range(len(p_list)), key=p_list.__getitem__)
    q_out, prev = [0.0] * m, 1.0
    for rank in range(m, 0, -1):
        prev = min(prev, p_list[order[rank - 1]] * m / rank)
        q_out[order[rank - 1]] = min(1.0, prev)
    return q_out
```

## 2. [주제 2] 유효 차원(`PR` vs `90% 주성분 개수`): 왜 숫자가 헷갈렸을까요?

### 2.1 쉬운 설명: 큰 기둥만 세는 자(`PR`) vs 잔가지까지 세는 자(`PC90`)
512개의 뉴런 출력에 주성분 분석(PCA)을 해서 각 축의 크기(분산)를 큰 순서대로 줄 세웠다고 해봅시다. **안채원 선생님**의 `effdim2_summary.json`에는 두 가지 지표가 함께 계산되어 있습니다:
1. **`PR` (Participation Ratio, 참여율)**: 가장 큰 기둥 몇 개가 전체를 얼마나 독차지하는지 봅니다. 수식 분모에 제곱($\sum \lambda_i^2$)이 들어가기 때문에 **맨 앞의 아주 큰 축 4~5개만 크면 뒤쪽 잔가지가 어떻게 바뀌든 숫자가 5~6으로 거의 고정**됩니다.
2. **`PC90` (`pc90_z`, 90% 분산 주성분 개수)**: 큰 기둥부터 차례로 더해서 **전체의 90%를 채우려면 축이 몇 개 필요한지** 셉니다. 뒤쪽에 자잘한 잡음 축이 많이 퍼져 있으면 숫자가 크고(`55개`), 모델이 쓸모없는 잡음 축을 정리해 압축하면 숫자가 뚜렷하게 줄어듭니다(`28개`)!

## 3. [주제 3] 같은 환자 검증 손실(`0.0970`) vs 새 환자 복원 손실(`0.2791`)의 진짜 이유

### 3.1 쉬운 설명: 왜 `newsubj_cell.py`에서 손실이 `0.2791`(2.88배)로 나왔을까요?
이전 검토 문서에서 `0.0970 -> 0.2791 (2.88배)` 숫자만 보고 *"새로운 환자에게 가면 모델 복원 오차가 2.88배나 폭증한다!"*고 적혀 있어서 당황스러우셨을 수 있습니다. **우리가 두 평가 스크립트(`gen_gap_eval.py` vs `newsubj_cell.py`)를 한 줄씩 비교해 본 결과, 모델 탓이 아니라 시험지 단위가 달랐기 때문임을 밝혀냈습니다!**

1. **원인 A (`newsubj_cell.py:68, 94` 입력 전압 `/ 2.0` 누락)**:
   - 사전학습 코드(`dataloader_utils.py:452`)와 같은 환자 평가 코드(`gen_gap_eval.py:85-86`)는 `collate` 함수 안에서 침습 뇌파(iEEG) 전압을 먼저 **`/ 2.0`**으로 나눈 뒤, 다시 `args.input_scale`(`100.0`)로 나누어 **총 `200 uV = 1.0`** 단위로 모델에 넣습니다.
   - 그런데 새 환자 평가 스크립트(`newsubj_cell.py`)는 `collate`를 거치지 않고 직접 텐서를 만들면서 `100.0`으로만 나누고 **`/ 2.0`을 빠뜨렸습니다(`100 uV = 1.0`)**!
   - 입력 신호 크기가 **2배** 커지면, 제곱 오차(MSE = `(예측 - 정답)^2`)는 신호 진폭 제곱에 비례해 커지므로 모델 성능이 똑같아도 손실 숫자가 2~4배 크게 찍히게 됩니다.
2. **원인 B (시험 창 길이 `3초 N=3` vs `1초 N=1` 차이)**:
   - `gen_gap_eval.py`는 3초(`N=3` 패치) 창을 씁니다. 한 전극의 가운데 1초가 가려져도 **같은 전극의 앞·뒤 1초가 살아 있어서** 힌트가 많습니다.
   - 반면 `newsubj_cell.py`가 읽은 BYD·Pippi 평가 파일은 창 길이가 **1초(`tokens_used: [1]`)**뿐입니다. 어떤 전극 패치가 마스킹되면 **그 전극의 시간 신호가 100% 사라져서** 오직 옆 전극들만 보고 맞혀야 하므로 원래 더 어려운 문제입니다.
3. **그렇다면 이미 뽑아 둔 `newsubj_summary.json`에서 진짜로 의미 있는 숫자는 무엇인가요?**:
   - 절대값 `0.2791`은 위 두 차이 때문에 `0.0970`과 직접 비교하면 안 되지만, **똑같은 `newsubj_cell.py` 안에서 `1/1024 모델`과 `전체(Base) 모델`을 비교한 상대 변화율 `-0.06% [-1.34%, +1.21%]`는 조건이 100% 같으므로 완전히 유효합니다!**
   - 즉, **"학습에 썼던 37명 환자의 다른 기록에서는 5시간 모델 손실이 +8.5% 나빠졌지만(그 37명의 세부 파형을 덜 외웠기 때문), 아예 처음 보는 새 환자에서는 5시간 모델과 5,203시간 모델의 복원 손실 차이가 -0.06%로 똑같았다!"**는 뜻이며, 오히려 **안채원 선생님**과 **이아현 선생님**의 핵심 해석을 멋지게 지지해 주는 증거입니다!

### 3.2 원고에 바로 붙여 넣는 문장 (재실험 불필요!)
- **그림 3(b) 캡션**: **안채원 선생님**께서 초안 61번째 줄 메모에 적어 두신 대로 `"Held-out reconstruction loss on unseen records from the same 37 pretraining subjects (2% record split)"`으로 쓰시면 완벽합니다.
- **본문 Results(실험 1 끝) 또는 Limitations 1문장 추가**:

### 3.3 (투고 후 선택) 만약 `newsubj_cell.py` 스케일을 고쳐 다시 재보고 싶다면?
